# Getting Support

Start with the affected project's README, documentation, release notes, and
supported-version policy. Search existing issues before opening a new one.

## Bugs

Use the bug report form in the relevant repository. Include a reproducible example,
version or commit, environment, expected result, actual result, and sanitized logs.
For a problem with the organization profile itself, open the report in this repository.

## Feature requests

Use a feature request to explain a workflow problem and the outcome you need.
Include alternatives you considered. Requests inform priorities without guaranteeing
implementation or a delivery date.

## Usage questions

Use the support channel documented by the project. Discussions should be used only
where they are enabled and offered for support. Do not file a feature request merely
to ask how an existing feature works. If no support channel is published, use the
documentation form to identify the specific missing instructions that block you.

## Sensitive reports

Public issues are not a channel for vulnerabilities, credentials, customer data,
or private incident reports. Follow [SECURITY.md](SECURITY.md) for vulnerabilities
and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for conduct concerns.

Support is provided as maintainer availability permits; this repository does not
establish a paid support contract or response-time commitment.
