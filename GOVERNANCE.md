# Governance

DevTechx Labs is an early-stage company. Its GitHub repositories use a lightweight
maintainer model, with company owners accountable for direction and access.

## Maintainers and decision ownership

Organization owners assign repository maintainers and manage permissions.
Maintainers make day-to-day technical and review decisions within their repository.
Company owners retain final responsibility for public releases, brand changes,
licensing decisions, and changes that affect the organization as a whole.

## Review expectations

Use pull requests for substantive changes. Explain the problem, tradeoffs, and
validation, and keep discussion attached to the change. Seek an independent review
where a second maintainer is available. If an owner must make an urgent correction,
record the reason and arrange a follow-up review.

For disagreements, document the options and ask the repository maintainer to decide.
Escalate unresolved decisions affecting multiple projects to an organization owner.

## Security-sensitive changes

Changes to workflows, permissions, dependencies, release automation, or disclosure
channels need explicit review by an owner or a maintainer responsible for security.
Keep vulnerability details in the private process described in [SECURITY.md](SECURITY.md).
Restrict access to the people needed to investigate and fix the issue.

## Community participation

Contributions are evaluated on usefulness, correctness, and maintainability.
Regular contributions may lead to a discussion about maintainer responsibilities;
access is granted deliberately and reviewed as responsibilities change.
No contribution guarantees a roadmap commitment or a maintainer role.

Changes to this governance model should be proposed in a pull request and approved
by an organization owner.
